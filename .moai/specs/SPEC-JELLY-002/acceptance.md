# SPEC-JELLY-002: Acceptance Criteria

## 개요

SPEC-JELLY-002의 수용 기준서. 각 모듈별 Given-When-Then 시나리오, 엣지 케이스, 품질 게이트를 정의한다.

**모든 수용 기준이 충족되었으며 2026-05-09에 완료되었다.**

---

## 모듈 1: AI 감정 분석 (MOD-AI)

### AC-AI-001: 정상 감정 분석 플로우

**Given** 사용자가 홈 페이지에 있고 EmotionInput 컴포넌트가 렌더링되어 있다
**When** "오늘 하루가 너무 행복해!" 텍스트를 입력하고 제출 버튼을 누르면
**Then**
- 로딩 인디케이터가 표시된다
- 제출 버튼이 비활성화된다
- API 응답 후 감정 타입 "joy"가 감지된다
- jellyStore.lastEmotion이 "joy"로 업데이트된다
- 감정에 해당하는 색상의 구슬이 5-15개 생성된다
- 분석 결과가 emotionHistory에 추가된다

### AC-AI-002: API 오류 처리

**Given** 사용자가 텍스트를 입력했다
**When** AI API 호출이 네트워크 오류로 실패하면
**Then**
- 에러 메시지가 입력 영역에 표시된다
- "다시 시도" 버튼이 나타난다
- 물리 엔진은 정상 동작을 유지한다
- jellyStore.analysisError에 에러 내용이 저장된다

### AC-AI-003: API 타임아웃

**Given** 사용자가 텍스트를 입력하고 제출했다
**When** API 응답이 10초 이내에 도착하지 않으면
**Then**
- 요청이 취소된다 (AbortController)
- 타임아웃 에러 메시지가 표시된다
- 로딩 인디케이터가 사라진다
- 재시도가 가능한 상태로 복원된다

### AC-AI-004: API 키 보안

**Given** 애플리케이션이 프로덕션 환경에서 실행된다
**When** 클라이언트 번들을 검사하면
**Then** OpenAI API 키가 번들에 포함되지 않는다
**And** API 호출은 서버 사이드 Route Handler를 통해서만 수행된다

## 모듈 2: 감정 기반 색상 전환 (MOD-COLOR)

### AC-COL-001: 감정 색상 전환

**Given** 젤리가 기본 색상(#FFD1DC)으로 렌더링되어 있다
**When** AI 분석 결과 "sadness" 감정이 감지되면
**Then**
- 젤리 바디 backgroundColor가 #6BCB77로 전환된다
- 글로우 효과 rgba 색상이 #6BCB77 기반으로 전환된다
- 전환이 800ms에 걸쳐 부드럽게 진행된다
- 전환 중 60fps 물리 렌더링이 유지된다

### AC-COL-002: 연속 감정 변화

**Given** 젤리가 "joy" 색상(#FFD93D)으로 렌더링되어 있다
**When** 사용자가 새로운 텍스트를 입력하여 "anger" 감정이 감지되면
**Then**
- 색상이 #FFD93D에서 #FF6B6B로 전환된다
- 중간 색상 없이 직접 전환된다
- 전환 애니메이션이 정상 동작한다

### AC-COL-003: 5가지 감정 전체 색상 매핑

**Given** 각 감정 타입별로 분석이 완료된다
**When** 다음 감정이 감지되면
**Then** 해당 색상이 정확히 적용된다:
- joy → #FFD93D (노란색)
- sadness → #6BCB77 (초록색)
- anger → #FF6B6B (빨간색)
- fear → #4D96FF (파란색)
- disgust → #A8E6CF (민트색)

### AC-COL-004: 기본 색상 복원

**Given** 앱이 새로고침된다
**When** 페이지가 다시 로드되면
**Then** 젤리는 기본 색상 #FFD1DC로 렌더링된다

## 모듈 3: 텍스트 입력 UI (MOD-INPUT)

### AC-INP-001: 텍스트 입력 및 제출

**Given** EmotionInput 컴포넌트가 렌더링되어 있다
**When** "오늘 정말 화가 나" 텍스트를 입력하고 엔터 키를 누르면
**Then**
- AI 감정 분석이 시작된다
- 로딩 상태가 표시된다
- 제출 후 입력 필드가 비활성화된다

### AC-INP-002: 글자 수 제한

**Given** 사용자가 텍스트를 입력 중이다
**When** 450자 이상을 입력하면
**Then** 글자 수 카운터 색상이 경고색으로 변경된다
**When** 500자에 도달하면
**Then** 추가 입력이 차단된다

### AC-INP-003: 빈 입력 방지

**Given** 입력 필드가 비어 있다
**When** 공백만 입력하고 제출하려고 하면
**Then** 제출 버튼이 비활성화 상태로 유지된다
**And** AI API가 호출되지 않는다

### AC-INP-004: 분석 결과 시각 피드백

**Given** AI 분석이 완료되었다
**When** 분석 결과가 수신되면
**Then**
- 감지된 감정 한글명이 표시된다 (예: "분노")
- 감정 색상으로 결과 영역이 표시된다
- 2초 후 입력 필드가 초기화되고 다음 입력이 가능해진다

## 모듈 4: 토스 브릿지 연동 (MOD-TOSS)

### AC-TOS-001: WebView 환경 감지

**Given** 앱이 Toss AppInToS WebView에서 실행된다
**When** 앱이 초기화되면
**Then**
- WebView 환경으로 감지된다
- tossStore.isWebView가 true로 설정된다
- Bridge 연결이 시도된다

### AC-TOS-002: 사용자 정보 읽기

**Given** Toss Bridge가 성공적으로 연결되었다
**When** 사용자 정보를 요청하면
**Then**
- 사용자 이름이 읽어와진다
- 사용자 ID가 읽어와진다
- 정보가 tossStore.userInfo에 저장된다

### AC-TOS-003: 일반 웹 폴백

**Given** 앱이 일반 브라우저에서 실행된다
**When** Bridge 연결을 시도하면
**Then**
- Bridge 미지원으로 감지된다
- tossStore.isWebView가 false로 설정된다
- 사용자 정보가 "게스트"로 설정된다
- 모든 핵심 기능이 정상 동작한다
- 에러 메시지가 표시되지 않는다

### AC-TOS-004: Bridge 응답 타임아웃

**Given** Toss Bridge가 응답하지 않는다
**When** Bridge 호출이 5초 이내에 응답하지 않으면
**Then** 일반 웹 모드로 폴백한다
**And** 콘솔에 정보성 로그가 출력된다

## 모듈 5: 다크 모드 테마 (MOD-THEME)

### AC-THM-001: 수동 테마 전환

**Given** 앱이 라이트 모드로 실행 중이다
**When** 사용자가 테마 토글 버튼을 누르면
**Then**
- 다크 모드로 전환된다
- html 요소에 dark 클래스가 추가된다
- 배경, 텍스트, 네비게이션 색상이 어두운 팔레트로 변경된다
- 전환이 300ms에 걸쳐 부드럽게 진행된다
- 선택이 localStorage에 저장된다

### AC-THM-002: 시스템 테마 감지

**Given** OS 시스템이 다크 모드로 설정되어 있다
**When** 앱이 처음 로드되면
**Then**
- 시스템 다크 모드가 자동으로 감지된다
- 앱이 다크 모드로 시작된다
- 시스템 테마 변경 시 실시간으로 반영된다

### AC-THM-003: 테마 영구 저장

**Given** 사용자가 다크 모드를 선택했다
**When** 앱을 새로고침하면
**Then**
- localStorage에서 "dark" 값을 읽어온다
- 앱이 다크 모드로 시작된다
- FOUC(깜빡임) 없이 즉시 다크 모드가 적용된다

### AC-THM-004: 젤리 가시성

**Given** 앱이 다크 모드로 실행 중이다
**When** 젤리가 화면에 렌더링되면
**Then**
- 젤리 글로우 효과가 라이트 모드보다 밝게 표시된다
- 젤리 표정(눈, 입)이 어두운 배경에서도 명확히 보인다
- 감정 색상이 다크 모드에서도 정확히 표현된다

### AC-THM-005: 테마 전환 중 물리엔진 유지

**Given** 물리 엔진이 60fps로 동작 중이다
**When** 사용자가 테마를 전환하면
**Then**
- requestAnimationFrame 루프가 중단되지 않는다
- 프레임 드롭이 발생하지 않는다
- 구슬 물리 시뮬레이션이 정상 동작한다

## 엣지 케이스

### EC-001: API 호출 중 앱 이탈
**시나리오**: 분석 요청 후 사용자가 다른 페이지로 이동
**기대 동작**: API 응답이 도착해도 무시되며, 메모리 누수가 발생하지 않는다 (cleanup 시 abort).

### EC-002: 연속 빠른 입력
**시나리오**: 분석 완료 전 사용자가 빠르게 여러 번 제출
**기대 동작**: 분석 중에는 제출 버튼이 비활성화되어 중복 요청이 방지된다.

### EC-003: 매우 짧은 텍스트
**시나리오**: 1-2자 텍스트 입력 (예: "ㅠ")
**기대 동작**: API 호출이 정상 수행되며, 분석 결과에 따라 감정이 결정된다.

### EC-004: 다크 모드 + 감정 색상 충돌
**시나리오**: 다크 모드에서 sadness(#6BCB77, 초록) 감정 젤리
**기대 동작**: 젤리 바디는 감정 색상 그대로, 글로우 효과는 밝기 증가로 가시성 확보.

### EC-005: Toss Bridge 부분 실패
**시나리오**: Bridge는 감지되지만 사용자 정보 읽기만 실패
**기대 동작**: isWebView는 true 유지, userInfo는 null, 폴백 메시지 없이 동작.

### EC-006: localStorage 비활성 환경
**시나리오**: 시크릿 모드 또는 localStorage 비활성 브라우저
**기대 동작**: 테마 저장 실패 시 에러 없이 세션 내에서만 유지, 새로고침 시 시스템 테마로 복원.

### EC-007: 모든 감정 연속 변화
**시나리오**: 5가지 감정을 연속으로 분석하여 색상 전환
**기대 동작**: 각 전환이 800ms 애니메이션으로 부드럽게 이어지며, 중간 색상 꼬임 없이 최종 색상으로 전환.
