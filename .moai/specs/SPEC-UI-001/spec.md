# SPEC-UI-001: 감정 리포트 시각적 디자인 개선

## HISTORY

- 2026-05-12: v1.0.0 초기 SPEC 작성. research.md 기반 현재 구현 분석 완료. 텍스트 전용 카드에서 데이터 시각화 중심 리포트로 전환 요구사항 정의.

---

## 1. 개요

마음 젤리 홈 화면의 감정 리포트 영역을 텍스트 전용 카드에서 데이터 시각화 중심의 인터랙티브 리포트로 개선한다. 사용자가 자신의 감정 패턴을 직관적으로 이해하고, 정화 여정을 시각적으로 확인할 수 있도록 차트, 그래프, 인터랙티브 요소를 도입한다.

### 배경

현재 감정 리포트는 `src/app/home/page.tsx` 415-465행에 위치한 단일 텍스트 카드로 구성되어 있다. glass-card 패턴과 감정별 동적 색상 텍스트를 제공하지만, 데이터 시각화 요소가 전혀 없어 사용자 참여도와 감정 인사이트 전달에 한계가 있다.

### 브랜드 정체성

모든 시각 요소는 브랜드 철학 "스트레스는 귀여움으로 녹는다"를 준수해야 한다. 감정 분석 용어("관리", "분석", "측정", "효율") 대신 힐링 용어("삼키다", "정화", "토닥토닥", "먹다")를 사용한다.

---

## 2. 요구사항

### REQ-VIS-001: 주간 감정 트렌드 차트

**When** 사용자가 감정 리포트 영역을 조회하면, **the system shall** 최근 7일간의 감정 변화 추이를 라인 차트로 표시한다.

- X축: 요일(월-일)
- Y축: 감정 빈도수
- 각 감정은 9개 감정 컬러 시스템(`EMOTION_COLORS`)의 색상으로 표시
- 차트 컨테이너는 기존 `glass-card` 패턴을 따른다
- 데이터가 없는 날은 점선으로 연결하여 시각적 연속성 유지

### REQ-VIS-002: 감정 분포 도넛 차트

**When** 감정 리포트가 표시되면, **the system shall** 전체 감정 중 각 감정의 비율을 도넛 차트로 시각화한다.

- 9개 감정 각각의 비율을 퍼센트로 표시
- 각 섹터는 해당 감정의 `EMOTION_COLORS` 색상 사용
- 중앙에 가장 빈번한 감정의 아이콘과 퍼센트를 표시
- 섹터 클릭/터치 시 해당 감정의 상세 정보 툴팁 표시
- 5% 미만 감정은 "기타"로 통합 표시

### REQ-VIS-003: 향상된 시각적 계층 구조

**While** 감정 리포트가 표시되는 동안, **the system shall** 3단계 시각적 계층 구조를 제공한다.

1. **요약 레이어**: 상단에 주요 감정 아이콘 + 한 줄 요약 메시지 (기존 `currentTheme.message` 패턴 유지)
2. **시각화 레이어**: 중간에 차트 영역 (트렌드 차트 + 분포 차트)
3. **인사이트 레이어**: 하단에 개인화된 조언 (`currentTheme.advice` 패턴 유지)

### REQ-VIS-004: 인터랙티브 요소

**When** 사용자가 차트 요소와 상호작용하면, **the system shall** 다음 인터랙티브 반응을 제공한다.

- 차트 데이터 포인트 호버/터치: 해당 날짜의 감정 상세 툴팁 표시
- 도넛 차트 섹터 클릭: 해당 감정의 일별 상세 내역 슬라이드업 패널
- 차트 영역 스와이프: 주간/월간 뷰 전환
- 모든 인터랙티브 요소는 `transition-all duration-300` 애니메이션 패턴 준수

### REQ-VIS-005: 차트 애니메이션 시스템

**When** 감정 리포트가 화면에 나타나면, **the system shall** 다음 애니메이션 시퀀스를 실행한다.

1. 리포트 카드: 기존 `animate-fade-in` 유지 (1000ms ease-out)
2. 차트 영역: 데이터 포인트가 순차적으로 나타나는 draw-in 애니메이션 (1500ms)
3. 도넛 차트: 중심에서 외곽으로 확장하는 reveal 애니메이션 (1200ms)
4. 인사이트 텍스트: 기존 `animate-fade-in-delayed` 유지
- `prefers-reduced-motion` 미디어 쿼리가 활성화된 경우 모든 애니메이션 즉시 완료 상태로 표시

### REQ-VIS-006: 개인화 기능

**Where** 사용자의 감정 데이터가 7일 이상 축적된 경우, **the system shall** 다음 개인화된 인사이트를 제공한다.

- 가장 자주 정화한 감정 순위 (상위 3개)
- 감정 패턴 변화 감지 (예: "이번 주 슬픔이 줄었어!")
- 연속 정화 일수 스트릭 표시 (불꽃 아이콘 + 일수)
- 개인화 메시지에 사용자 이름(`userName`) 포함 유지

### REQ-VIS-007: 접근성 준수

**The system shall** WCAG 2.1 AA 수준의 접근성을 모든 시각화 요소에 제공한다.

- 모든 차트에 `role="img"` 및 `aria-label` 속성 포함
- 차트 데이터를 스크린 리더가 읽을 수 있는 대체 텍스트 테이블 제공
- 색상 대비율 4.5:1 이상 (텍스트), 3:1 이상 (시각적 요소)
- 키보드 네비게이션 지원 (Tab 키로 차트 요소 간 이동)
- 터치 타겟 크기 최소 44x44px 준수
- `prefers-reduced-motion` 존중

### REQ-VIS-008: 브랜드 일관성

**The system shall** 모든 새로운 시각 요소에서 기존 디자인 시스템을 준수한다.

- 차트 컨테이너: `glass-card rounded-3xl` 패턴
- 폰트: `font-gamja` (본문), `font-jakarta` (라벨/캡션)
- 아이콘: Material Symbols Outlined with `fontVariationSettings: "'FILL' 1"`
- 감정 색상: `EMOTION_COLORS` 상수 사용 (하드코딩 금지)
- 배경: 감정별 그라디언트 (`emotion-bg-*-start/end`) 활용
- 그림자: 기존 `shadow-sm` ~ `shadow-lg` 범위 사용

### REQ-VIS-009: 반응형 대응

**While** 다양한 화면 크기에서 서비스가 이용되는 동안, **the system shall** 레이아웃이 화면 크기에 맞게 조정된다.

- 모바일 (320-428px): 차트 세로 스택 배치, 전체 너비
- 태블릿 (429-768px): 차트 가로 2열 배치 가능
- 토스 미니앱 환경: `max-w-md` 제약 유지
- 차트 크기는 컨테이너 너비에 비례하여 자동 조정

### REQ-VIS-010: 성능 제약

**If** 차트 렌더링으로 인해 페이지 로딩 시간이 증가하는 경우, **then** the system shall 다음 최적화를 적용한다.

- Recharts 라이브러리 동적 import (`next/dynamic` 사용)
- 차트 데이터 캐싱 (클라이언트 사이드)
- 애니메이션 프레임레이트 60fps 유지
- 번들 사이즈 증가량 50KB 이하 (gzip 기준)
- 초기 렌더링 지연 200ms 이하

## 3. 제약사항

### 기술 제약

- 차트 라이브러리: Recharts 사용 (React 통합성, 번들 사이즈, 커스터마이징 균형)
- 기존 9개 감정 컬러 시스템(`EMOTION_COLORS`)과의 호환성 필수
- Next.js App Router 환경에서의 클라이언트 컴포넌트 동작 보장
- Toss 미니앱 WebView 환경에서의 안정적 렌더링

### 디자인 제약

- 기존 `glass-card` 디자인 패턴 유지
- 브랜드 보이스 가이드 준수 (반말, 힐링 용어)
- 다크 모드 지원 (기존 다크 모드 시스템과 통합)
- Material Symbols Outlined 아이콘만 사용

### 데이터 제약

- 감정 데이터는 로컬 스토리지 기반 (API 의존성 최소화)
- 데이터가 없는 상태에서의 graceful degradation 필수
- 최대 30일치 데이터까지만 차트에 표시
