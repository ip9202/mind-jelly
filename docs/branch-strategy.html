워크플로우

🚀 기능 개발 플로우
  1. 브랜치 생성: develop에서 feature/spec-xxx 분기
  2. SPEC 구현: TDD/DDD 방법론으로 기능 구현 + 테스트
  3. PR 생성: feature/spec-xxx → develop PR 오픈
  4. 리뷰 & 머지: 테스트 통과 확인 후 develop에 머지
📦 릴리즈 플로우
  1. 릴리즈 브랜치 생성: develop에서 release/vX.Y.Z 분기
  2. 버전 bump & QA: package.json 버전 업데이트, CHANGELOG 작성
  3. main 머지: release/vX.Y.Z → main 머지 + 버전 태그
  4. develop 동기화: release/vX.Y.Z → develop에도 머지
  5. 배포: main에서 npx ait deploy --memo "vX.Y.Z"
🔥 핫픽스 플로우
  1. 핫픽스 브랜치 생성: main에서 hotfix/issue-name 분기
  2. 버그 수정: 최소 변경으로 버그만 수정, 테스트 추가
  3. main 머지: hotfix/issue-name → main + 태그 (vX.Y.Z+1)
  4. develop 동기화: hotfix/issue-name → develop에도 머지 (이중 머지 필수)

버전 네이밍 규칙

MAJOR (X.0.0)
하위 호환 불가 변경
예: React Native 전환, 데이터베이스 스키마 대규모 변경
MINOR (X.Y.0)
하위 호환 기능 추가
예: 친구 시스템, 온보딩, 새로운 스킨
PATCH (X.Y.Z)
버그 수정, 핫픽스
예: 젤리 히트박스 수정, 광고 ID 교체

Git 태그 규칙

모든 릴리즈와 핫픽스는 main 머지 후 즉시 태그를 생성합니다.
